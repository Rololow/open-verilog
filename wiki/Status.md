# Status and compatibility

## Examples

All the examples in `examples/` compile with `ovc`. Twenty-one of them produce output identical to the Python reference
(`expected/`), and the golden tests check that byte for byte:

`adder`, `bits`, `bundle`, `cdc`, `classes`, `config`, `counter`, `fsm`, `hier`, `isa`, `loops`, `methods`, `mixed`,
`nested`, `pipe`, `probes`, `structs`, `systolic`, `testbench`, `types`, `widths`.

`chain`, `pipeline` and `qol` compile but are not golden. Their pipelines name the valid bits and the carried registers
after the stages (`ov_valid_add`, `s__add`) instead of by index. That is a deliberate change, for readability. Their
behaviour was checked by simulation.

## Compatibility with the Python reference

The Rust compiler is the port of the Python reference, which stays the reference for behaviour. On large designs the
text can differ from the Python output: the Rust output does not write the `// Generated by ovc` header, and it keeps a
signal for some `val`s that the reference inlines. Simulate a design with both before you rely on the Rust output
alone.

The clock-domain checks (crossings, `same_domain`, `async` ports and memories) and the reset and valid/ready checks are
the same as in the Python reference: the same messages, on the examples and on a set of targeted cases.

## Not implemented

- `lint` and `cover` subcommands.
- Asynchronous pipeline resets (`reset NAME async;`): pipelines are reset synchronously.
